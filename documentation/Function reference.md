# Holidaze function reference

This reference covers named functions in `src`, including React components, local handlers and message helpers. Each source file appears once. The API error constructor is listed separately with its client. Small anonymous callbacks belong to their owning function.

Each section starts with the flow between its parts. The tables locate the functions in their source files.

## 1. Startup and navigation
`main.jsx` restores the saved theme and mounts the router and account provider. `App` selects the route. `Layout` supplies the shared page shell, while `AccountLayout` adds account navigation inside protected routes. Layout resets route content on pathname changes. BookingReview additionally resets its review when the search selection changes.

Sessions without an expiry rely on API responses. `logout`: Clears the saved session, shared profile and query cache, optionally showing a notice. `login`: Signs in through Noroff and stores the returned account session. `request`: Adds the access token, ends expired sessions on HTTP 401 and handles authenticated request errors. `becomeManager`: Enables hosting and updates the session only if the same account is still signed in. |

## 3. API requests and saved data
All API reads use TanStack Query and shared `queryKeys` builders. Page-entry effects handle scrolling separately from requests, so retrying preserves the scroll position. Query functions forward their AbortSignal to cancel obsolete requests. Public venue requests use `apiRequest`. Account functions receive the authenticated `request` from `AuthProvider`. `getAllPages` collects complete lists. TanStack Query caches public venue lists and manager venues for two minutes per data variant. Venue and booking operations cancel obsolete reads and invalidate the lists after each write attempt, including uncertain outcomes. Save handlers return errors to their forms and avoid automatic retries after uncertain creation results. The shared hooks have separate roles: useAuth supplies account context, useManagerVenues shares an account-specific read, and useSubmit guards form and confirmation actions. In Function Flows, their file/function descriptions are collected in section 10; the page flows show where they are used.

| File | Functions and responsibilities |
| --- | --- |
| `src/hooks/useSubmit.js` | `useSubmit`: Supplies submit, run, pending, error, fieldErrors, setError and the shared busy ref to authentication, profile/role changes, venue forms/deletion and booking confirmation/edit/cancellation. `run`: Locks synchronously against duplicate actions, clears previous errors, awaits the supplied save action and always unlocks afterwards. Direct or wrapped Zod issues become field errors by path and a deduplicated summary; other failures use their message. `submit`: Prevents native form submission and passes the form element to run. Validation and API writes remain in the supplied action. |
| `src/api/queryClient.js` | Shares the TanStack Query client and read defaults. Detail and account queries are released on exit. Public and manager lists retain a five-minute lifetime and a two-minute freshness window. `invalidateVenueQueries` cancels obsolete list and host-profile reads and invalidates their shared prefixes after venue or booking writes. |
| `src/hooks/useManagerVenues.js` | `useManagerVenues`: Uses useAuth and queryKeys.managerVenues(user.name) to share the complete owned-venue list, including bookings, across ManagerOverview, MyVenues and VenueBookings. Its query forwards the cancellation signal to getProfileVenues. Data stays fresh for two minutes and unused data remains cached for five. Optional select derives view-specific data without changing the shared cached list; the hook returns TanStack Query's data, error and refetch state. |
| `src/api/queryKeys.js` | `queryKeys` supplies prefixes and key builders. `venueList` and `managerVenues` share the venue-list prefix. `profileBookings` shares the booking-list prefix. `hostProfile` uses the public-profile prefix and includes the viewer. `venue` identifies shared public details. `ownVenue`, `ownBooking`, `editableBooking`, `venueBooking` and `ownProfile` isolate ownership-checked data by account and purpose. |
| `src/api/venueQueries.js` | `venueOptions`: Shares the venue key and cancellable detail request between Venue Details and Booking Review. `venueListOptions`: Defines two-minute public venue-list queries, always including owners and keyed by optional booking data. Used by Home and Explore. |
| `src/api/client.js` | `isCreateOutcomeUncertain`: Tells booking and venue creation when a failed request may already have saved the record. `getAllPages`: Loads complete pages of 100 records and keeps the latest record for each ID. `ApiError.constructor`: Keeps an API error message, HTTP status and field errors together. `apiRequest`: Sends JSON requests to Noroff, preserves pagination metadata and adds the default API key only to authenticated calls. |
| `src/api/venues.js` | `createVenue`: Validates and creates one venue, marking uncertain responses to prevent duplicate saves. `getOwnVenue`: Loads a venue and checks that it belongs to the signed-in account. `deleteVenue`: Checks ownership before deleting a venue and invalidating cached lists. `updateVenue`: Validates and saves an owned venue, explicitly clearing removed location fields. `getVenue`: Loads one venue with its owner and booking data. `getAllVenues`: Loads every public venue page with owner data and optional booking data. `sortVenues`: Sorts a copy of the venue list using a supported name, price or creation-date order. `filterVenues`: Applies text, capacity, amenities and reliable availability after Venues validates the selected dates. |
| `src/api/bookings.js` | `getProfileBookings`: Loads every booking page for a profile, including its venue data. `getBooking`: Loads a booking with its customer and venue for both ownership checks. `getOwnBooking`: Loads a booking and checks that its customer matches the signed-in account. `getVenueBooking`: Loads guest booking details only for the manager who owns the venue. `getEditableBooking`: Checks customer ownership and future dates when the editor opens and again before a change or cancellation. `updateBooking`: Rechecks an editable stay before saving. A changed price requires another review. `cancelBooking`: Checks ownership and future-stay eligibility before deleting a booking. `createBooking`: Rechecks availability and price before saving once. Uncertain outcomes block blind retries. |
| `src/api/profiles.js` | `getHostProfile`: Loads the profile and its complete venue and booking lists in parallel for public profile statistics, forwarding one cancellation signal to all reads. `getProfileVenues`: Loads every venue for a profile, newest first, optionally including bookings. |

## 4. Dates, prices and input validation
Date keys stay in `YYYY-MM-DD` format for comparisons, inputs and API values. Display helpers format dates and NOK amounts for the interface. `staySummary` combines validation and pricing, and both the interface and save operations check the selected stay. Check-out is excluded from booked nights. Saved-booking prices use the venue's current rate.

| File | Functions and responsibilities |
| --- | --- |
| `src/utils/availability.js` | `dateKey`: Creates a local ISO calendar key for comparisons and API values, not display. `addDays`: Moves an ISO calendar date by whole days using UTC arithmetic. `validDate`: Checks that a YYYY-MM-DD value represents a real calendar date. `stayFromSearch`: Reads stay dates and guest count from URL parameters. `staySummary`: Validates a stay and calculates its cost, excluding an edited booking when supplied. `stayPrice`: Calculates nights and total cost for a valid date range. `bookedPeriods`: Extracts booking ranges and flags unreliable data. Records with both dates already past are excluded for reservation checks. `overlaps`: Checks for overlapping stays, excluding the check-out date. `guestCountError`: Checks whole guest counts against known capacity and the allowed minimum. `validateStay`: Checks dates, guest capacity and availability before a reservation proceeds. |
| `src/utils/bookings.js` | `bookingDates`: Extracts calendar dates and guest count from a booking. `bookingStatus`: Classifies a booking using its arrival and departure dates. `bookingPrice`: Calculates a booking's cost using the venue's current nightly rate. `groupBookings`: Classifies each stay once. Hosts see current and upcoming groups separately, while guests see both in arrival order. `formatBookingDate`: Formats a date for English display, with a fallback for missing or invalid values. `formatBookingRange`: Formats a short date range without repeating shared months and years. `guestSummary`: Counts total, completed, upcoming and current stays and sums nights. Invalid dates leave the night total unknown. Unloaded data stays unknown and an empty list gives zero. |
| `src/utils/manager.js` | `managerBookingGroups`: Attaches venues to bookings, removes duplicate IDs and separates booking statuses. `managerSummary`: Calculates manager booking totals and the average of valid venue ratings. |
| `src/utils/venue.js` | `isPhotoUrl`: Checks whether a value has the HTTP(S) URL shape used for photo selection. `hasVenuePhoto`: Checks that the first venue photo has a usable URL shape. It does not load the image. `selectHighlyRatedVenues`: Filters for rating above 4.5, two distinct photo URLs and usable map coordinates, then shuffles the copied pool with Math.random. `formatVenuePrice`: Adds the nightly label to a formatted price, or supplies a missing-price message. `formatPrice`: Formats NOK with spaces between thousands and ,- for whole amounts. `venueMapLinks`: Returns a map URL string or null using the shared map-position rule. `formatLocation`: Formats city and country, falling back to continent and then the missing-location message. `formatAddress`: Formats a full venue address, omitting blank fields. |

## 10. Callbacks, configuration and checks
Effects start requests or attach browser listeners. Cleanup aborts obsolete requests, removes listeners and clears timers. State updater callbacks use the previous value when toggling or changing a collection. Rendering callbacks build cards, fields and calendar days. Filter, sort and reduce callbacks stay with the feature that uses them.

`vite.config.js` sets up React and Tailwind. `eslint.config.js` sets JavaScript, JSX and browser rules. Netlify routing and build settings live in `netlify.toml`. These files are configuration rather than application functions.

The retained test files are `tests/unit/availability.test.js` for booking/date calculations and guest validation, and `tests/e2e/navigation.spec.js` for the 404 route and signed-out account redirects at desktop and mobile widths. `tests/vitest.config.js` and `tests/playwright.config.js` configure those checks. Their anonymous test callbacks use the functions described above. See README for commands.
